# 候选规格：条件消息束与跨窗前瞻

版本：`reachability_stop/conditional-bundle-v2`。状态：**PROPOSED_NOT_IMPLEMENTED / WAITING_USER_REVIEW**。底层正式方法仍为完整 `raven_mcs/configured-design-v1`，主轨显式 Design=on，Gate仅诊断。本轮只形成规格，不实现、不拟合预测器、不运行本规格的内部预测或外部回放。

## 选择的单一修改方案

把“下一0.1步的即时投影收益”改成“条件化消息束下，不同首次关闭时点及其后续窗的释放质量积分”。控制变量仍只有 CLOSE/WAIT；不选择客户端、不改变训练骨干、目标系数、聚合约束或性能门槛。不是换名后的旧单步策略。

合计约50–82人时，含新增关键路径测试，尚未实测；这是人员工作量，不是本轮CPU预算，也不包括P2–P7实验、外部系统复现或任何性能承诺。概率假设不成立可能需要更改研究范围，不能以该估计掩盖方法可识别性问题。

## 状态、信息和冻结边界

动作输入 `DecisionSnapshot(s)`：当前时刻、窗起点/硬截止、服务器模型版本、合法未消费池、在途注册ID/注册时间/已知下载版本/公开资源、最近释放摘要、debt、lagged variance与估计器、公开目标目录及μ、冻结Design和算法参数。池内有已交付的校正质量与摘要；在途没有尚未交付的观测组成、成功结果、梯度或真实完成时间。

消息stage1 Design/p及局部训练权重在注册、获得合法观测信息时冻结并随消息保存，不能跨窗后用新的Design或未来p改写已经训练的更新。当前关窗的stage2 q模型、debt及P2参数使用其明确的lagged快照；每个字段保存 as_of 与方法版本。主轨Design恒on；Gate变化不进入动作或计算输入。

窗口前冻结控制器配置和预测器参数。当前窗允许用已发生的注册/交付条件化预测，不允许重新拟合参数；窗结束后只有已成熟的合法标签进入下一窗估计。配置和随机数键必须保存；固定on/off运行不通过数据集名选Design。

禁止输入旧U、旧tau、其他策略的下载版本、未来事件表、未来payload、隐藏成功随机数或标签。注册时必须区分真实已知 model_age 与后来形成的更新陈旧性。测试支持元数据只有能证明在部署前公开时可形成μ；原v1文件的TEST群组统计来源不自动满足新实验的时间可用性要求。

## 预测器：具体而有限的接口

保留共同20时间单位暖启动和原4场景数量，不把增大样本数作为解决方案。拟议预测器为离散条件服务风险表，步长0.1；资源分层取协议事先公开的设备/网络档位，字段缺失就报告接口不足，不从隐藏 tier 补齐。

每个层/服务年龄格，完成风险 `h_l=该格已观测完成数/该格仍处于风险集数`；已通知失败为竞争事件，校准截止后尚未完成为右删失，不当作已失败。暖启动之外的未来完成、成功及payload不参与拟合。资源层风险集不足5条时标 `UNSUPPORTED_PREDICTION`，不制造尾概率。按当前仍未完成条件得到残余服务分布。

完成标记用相同层的历史已交付**联合摘要**重采样：client、stage1群组质量、总质量、有效样本量及当时合法版本信息。当前在途client与下载版本已知，不重新抽取；未来注册只有事前公开的机会时钟可展开，client未知时使用历史机会分布。没有历史支持的目标群组标为未覆盖，不以μ生成理想消息。未来标记是经验预测而非真实payload。

未来摘要的variance由当前lagged状态及预测有效样本量计算；没有未来梯度输入。规划期间对未知的variance学习增量采用零增量近似，对已预测释放更新debt和版本。这个近似必须在后续校准/消融中报告，不能声称精确预测完整未来训练状态。

## 动作与目标：可编码规则

拟议常数：Δ=0.1、D=4、规划H=8时间单位（至实验T截断）、4条条件场景、age上限5、cap/ESS及P2全部沿用正式聚合器。H是覆盖至少一个后续窗的设计选择，不是搜索获得的最优值。无新增算法参数搜索；修改这些常数需独立规格修订。

预计每个决策最多6计划×4场景×5次预测释放=120次P2，另加当前预览与d求解；实现应缓存相同摘要，并记录实际次数。建议将2 CPU秒设为单决策规划上限，超时显式采用上述固定2后备、计入控制开销；必须由可中止的隔离规划器实现，不能让阻塞求解器跨越预算。2秒仅是待审计算预算，不是实测运行速度。其与模拟0.1时间单位没有自动的物理秒对应关系；后续若超时/后备使动作近同固定策略，原P3门槛仍会失败，不因此提高预算。

1. 在时刻s，用真实当前池构造完整P2输入；只读预览P2权重a和 `ell=0.5||M a−μ||₁`。另用**相同A**求 `d_s=min_a 0.5||M a−μ||₁`，用于当前可达性诊断，不替代ell。不接受仅可行解作为不可达证书。
2. 计划首次关闭偏移集合为 `{0,0.1,0.5,1,2,D−elapsed}`，大于剩余截止者删除，去重；当前K<3删除0。预测计划在选定时点K不足3时延至硬截止。截止必关，包括空池。
3. 生成4条共同条件场景，对每个计划在克隆状态上推进；首次关窗后按固定等待2的tail policy继续，直到共同H结束。所有计划共用同组原始预测随机数。这个tail是有界评估近似，**不是**重新获得fixed_time_2的真实性能优势保证。
4. 各预测释放调用相同完整P2摘要计算；消费合法池、处理替代/过期，维护在途及下一窗。非空且实际执行服务器更新才版本+1；空池关窗只更新窗起点，保持模型版本、debt和最近释放，另计empty closure。全部A层基线共享此新规则；不把这称为旧v1复现。
5. 在预测共同网格积分最近释放分数：`ell_release+0.02 age_normalized_release+0.20 duration_release/4`。此前无释放为1；当前尚未关窗期间继续保持真实最近释放摘要。取4场景均值最小的计划，完全相同（比较容差1e−7）时选择较早的关闭。只执行当前第一个网格动作，下一网格使用新合法历史重新规划。
6. 风险集/标记预测不受支持时，使用明确记录的fixed_time_2后备（最长4）；这包括K不足或空池。缺失/无效Design、p/q、P2输入或不合法数值是**接口错误并暂停**，不能走后备以掩盖方法不完整。记录后备比例；后备高或动作与固定策略近同仍须接受原P3机制门槛。

该规则保留旧0.02/0.20系数；改的是计划时域、条件核、完整聚合摘要和状态传播。新辅助J因组成/聚合器与空池语义改变不能直接接续旧J。C1主验收仍是原v2协议G/W两条路线，旧v1失败独立保存。

输出是经验动作、预计支持补齐及预测质量，不输出“未来一定不可达”、最优停止或alpha=0.05证书。即使模型内规划胜过即时计划，也不证明真实系统收益。

## 动态系统接口与概率依赖

拟议生产链：`on_register → start_local_training(downloaded checkpoint) → on_completion → admit/supersede/expire → snapshot/decide → release → consume/version/debt → mature estimation rows`。事件总线掌握外生服务，但只向控制器发当前可见事件；真实更新张量留在训练/释放模块，P2本身无需未来更新位移。

`preview_release(snapshot, pool)` 必须无副作用地复用当前 stage1摘要、q→reference、variance/staleness、完整P2。`apply_release(preview, updates)` 在仍相同快照下执行一次更新与消费；状态已变化则重新预览，不复用旧权重。`advance_forecast` 仅操作克隆摘要，绝不训练或产生声称为真实的预测。

现有 [window_runner.py](C:/Cursor/raven.mcs/src/raven_mcs/training/window_runner.py) 的固定WindowDataSlice/最终U不能直接用作动态事件源；[methods.py](C:/Cursor/raven.mcs/src/raven_mcs/aggregation/methods.py) 与 [p2_cvxpy.py](C:/Cursor/raven.mcs/src/raven_mcs/aggregation/p2_cvxpy.py) 可复用完整权重求解。新增模块拟放 `src/raven_mcs/control/`，其存在与行为均待批准后实现；本轮未创建这些模块。

关键概率接口定义为：`q_pi(x)=P(本次已注册且有合法观测的更新，在策略pi下最终被接受并消费 | 注册前合法历史及x)`。必须区分物理成功、到达可用、替代、过期、未消费和仍待定；若现有usable定义只覆盖到达而未覆盖消费，需单列消费选择概率或证明联合定义与原stage2估计量相容，不能换标签后宣称原理论不变。

现有 [usable.py](C:/Cursor/raven.mcs/src/raven_mcs/propensity/usable.py) 把deadline_slack_pre当注册特征。动态实际close在注册时未知，禁止事后填入。拟议模型特征只能含注册时已知的**最大截止余量**、当前版本/公开资源、已发生池/在途摘要与policy/config版本；lagged模型训练使用本策略所有成熟尝试，保留0结果与右删失。预测值逐尝试在注册时固定，参数只在允许的后续窗更新；规划复用该冻结模型，不用未来模拟结果反向拟合q，避免循环定义。

这个估计方案需要顺序条件选择/正性和足够的本策略历史覆盖；warmup固定策略记录不足以自动识别新策略q。若无合法本策略校准来源，B0只能通过与概率无关的独立子模块；B1/P1真实完整链不得启动。可以先申请另行限定预算的校准，但当前没有这种授权。若选择依赖不可见组成使假设失败，进入审查，不默默删IPW或沿用旧q。来源、成熟条件、校准、裁剪与支持必须在实施验收单中逐项核验。

## 最小验证与主张范围

批准实施后首先只验证新增关键路径：信息隔离、联合支持、多窗版本/消费、真实P2预览一致性、动态q的时间可用性以及一次保存恢复。确定性单元fixture不是收益实验；生成随机控制轨迹属于回放，需独立批准。旧226项Design身份检查按适用范围复用，新增动态快照只补冻结与Gate独立性检查，不重复整套。

后续真实16窗是接口验收；6类×100条为逻辑/预测检验；完整开发三种子才检验C1。C2需真实训练配对不退步；预测改善需另有RMSE优势证据。当前三者均未运行。本规格审查通过也不写 IMPLEMENTATION_ALIGNED 或主实验成立。
