# RAVEN-MCS 主实验重建协议设计

日期：2026-10-11。Owner：`ccf-experiment-designer`。Mode：`design / standard`。目标场景沿用现有 TMC 稿件。本文是实验设计，所有建议阈值、预算和新方法配置均为待冻结的设计参数；未生成新实验结果。

## 1. 要回答的问题与完成标准

按用户本轮要求，重新检验两种尚未排除的解释：旧预测结果是否由训练不足造成；聚合无收益是否由可行域退化造成。采用统一骨干、共同训练协议和逐级聚合对照，同时保留自然参与条件下的结果。

证据顺序必须是：**模型能学会任务 → 可行域允许有意义的调整 → 聚合规则改变更新 → 改变最终预测误差**。仅改善组失配不能替代最后一步。

建议将完成标准冻结为以下三项，并分别作结论：

1. **学习有效**：统一骨干的均匀聚合版本在充分训练后，优于训练均值和所有适用、同信息条件的持久性／季节性基线。建议实际意义阈值为相对 RMSE 改善 2%，并报告物理单位误差差值。2% 是本设计建议，不是既有结果或领域标准。
2. **机制有效**：预注册的高自由度主条件下，完整 RAVEN 相对均匀权重的改善达到上述阈值，区间支持正收益；并通过四臂差分区分校正、纯约束投影和其余目标项。
3. **主实验有效**：自然参与的全部窗口上仍有实际预测收益；若只在可控高参与场景有效，则完成的是条件机制验证，尚未完成自然参与主实验重建。

对“改善至少 2%”的强结论，需要置信下界超过 2%；均值超过 2%而下界只超过 0，只支持正收益及达到阈值的点估计。若实际部署存在明确误差容忍度，应在测试前以该尺度替换 2%。

## 2. 当前实现核对及设计影响

本轮直接读取了以下源码：

- `src/raven_mcs/models/common_ndmf.py`：Common-NDMF 使用空间 embedding、小时、星期、trend；当前没有历史观测分支，也没有 client-ID embedding。
- `src/raven_mcs/training/client.py`：本地是手写 SGD，返回 `(theta_base-theta_local)/(gamma*E_loc)`。
- `src/raven_mcs/training/window_runner.py`：服务器以 `theta -= eta*sum(alpha*u)` 更新。因此同步时相对原始客户端位移的系数为 `eta/(gamma*E_loc)`，增加本地步数并不等价于增加整体有效更新。
- `src/raven_mcs/correction/second_stage.py`：`beta_hat` 是截断可用性校正后的质量归一化。
- `src/raven_mcs/aggregation/methods.py`：`local_hajek` 的服务器权重是 raw-count 比例；`inst_cal` 除参考项外还保留组匹配、方差、陈旧度项；二者均不能直接充当本设计的“均匀权重”和“纯可行投影”。
- `src/raven_mcs/aggregation/method_policy.py`：当前声明的论文方法是 `raven_mcs / aggregate_coverage`；`raven` 是 legacy always-on。完整方法必须按实际论文方法核对 gate，不能只看历史方法名。

上述是当前文件的实现事实；交接文档里的历史数字仅作问题背景。本轮没有重新计算旧实验结果。

## 3. 数据、任务与信息条件：P0

### 3.1 数据范围

第一批使用 NSW-Traffic、SensorScope、U-Air。NSW-Traffic 是预定机制主数据集，SensorScope 和 U-Air 检验主实验能否推广；不能按新测试结果挑出最好的一块作为主数据集。T-Drive 和 City Scanner 作为后续真实机会／观测外部验证，不进入首批统一骨干搜索。

沿用合法的训练／验证／测试单元身份、原始部署目标和分组。新训练预算、骨干、参与调度与约束配置单独命名；新结果与旧表分开。无需通过集中目标 kappa 来制造优势。

### 3.2 先固定预测任务，避免把补全变成不同的预测任务

P0 写出每个数据集的预测时点、标签遮蔽规则、可见协变量、历史观测来源、可用时刻、采样间隔、目标变换和评价单位。

- 补全任务沿用其遮蔽／时间划分，不能为了持久性基线更换测试集。
- 只有可按时间合法取得历史观测时，持久性和 seasonal-naive 才作为主对照；严格离线评价默认只能使用训练期已交付历史。
- 如原任务允许部署期观测到达，则另设在线补全轨道。当前被评分标签始终遮蔽，只允许此前确实到达且未被遮蔽的观测作为历史；四臂和简单基线共享该信息条件。
- 若原划分不是时间外推，持久性基线采用“查询时点之前的合法观测”，不能直接读取前一个测试标签。
- 所有 scaler、插补、模型和季节周期选择只用训练／验证数据。主要训练信息来自合法已交付观测；完全可见训练标签另列 privileged diagnostic。
- 训练和评估必须使用同一特征提取与目标反变换。U-Air 等已有重计分路径需固定一个明确评分版本，不能拼接不同路径的数值。

### 3.3 简单而必要的预测基线

每个基线返回对全部测试查询的预测、历史是否可用、回退类型及覆盖率。不得只在其有历史的容易子集评分。

1. **训练均值**：全局均值，以及站点／空间单元均值。只用当前信息条件合法的训练标签；站点无训练数据时回退全局均值。另列旧稿 all-train 常数用于衔接，清楚标识信息来源。
2. **持久性**：同空间单元最后一个合法可见观测；记录观测年龄。无历史时按统一的站点／全局训练均值回退。
3. **季节性历史预测**：规则采样且对应周期有历史时使用 seasonal-naive；不规则采样则使用训练期拟合的空间单元×时段季节均值。日／周周期由时间分辨率及训练／验证决定，测试前冻结；回退顺序为站点×时段 → 站点 → 全局。
4. **Central-delivered**：同骨干、同合法交付样本、充分训练，作为学习／联邦优化参照；不把其池化访问与联邦系统称为同部署成本。
5. **Central-all**：全部合法训练标签，只用于区分信息不足与模型容量不足；不能作为可部署能力证书或聚合性能上界。

均值、naive、seasonal-naive 的标准定义参见 [Forecasting: Principles and Practice, 5.2](https://otexts.com/fpp3/toolbox.html#some-simple-forecasting-methods)。这里的信息遮蔽和回退规则是本任务的协议设计。

## 4. 统一骨干与充分训练：P1

### 4.1 骨干选择规则

优先充分训练现有 Common-NDMF，以隔离优化预算问题。当前模型缺少历史输入，不能预先保证它会超过持久性；若在验证集上未过关，允许一次预注册的骨干升级：**统一的历史条件残差骨干**。

升级版本保留空间／时间编码，增加最近 8 个合法历史观测的数值、mask、观测年龄、日／周滞后可用值及 mask，经过一个 `64→32` MLP；以训练均值／合法季节参考为基值预测残差。所有数据集采用相同结构和历史合法性规则，不加入 client-ID，不加入测试标签。没有历史时 mask 为零并使用共同回退。

骨干按跨三个数据集的验证集平均相对基线误差选择；只有所有数据集均过验证门槛的候选才能成为“三数据集有效统一骨干”。若没有候选通过，记录各数据集失败原因，停在学习阶段，不进入昂贵确认。该升级是待实现候选，不能标成现有已确认方法。

### 4.2 优化器与更新尺度

集中式初始候选：Adam，`betas=(0.9,0.999)`、`eps=1e-8`、weight decay 0，学习率 `{3e-4,1e-3,3e-3}`；SGD+momentum 0.9，学习率 `{1e-3,1e-2,3e-2}`。batch size 64，样本不足时使用全部样本。训练比较在相同样本处理预算上进行。这些是搜索起点，须由验证曲线确认。Adam 参数语义参见 [PyTorch Adam 文档](https://docs.pytorch.org/docs/2.14/generated/torch.optim.Adam.html)。

联邦训练优先使用本地 Adam，学习率同上，服务器原始位移系数 `rho∈{0.5,1.0}`；每次客户端调用重置本地 optimizer 状态，每次调用从各自合法模型版本开始，四臂保持一致。异步客户端使用真实 base snapshot，记录陈旧度，不能误用当前服务器参数构造位移。

设 `d_k=theta_base,k-theta_local,k`，统一服务器更新为：

`theta_next = theta_current - rho * sum_k(alpha_k * d_k)`。

这样本地优化器可以明确解释为产生一个模型位移。若复用原 SGD 归一化接口，必须设置 `eta=rho*gamma*E_loc` 才与该尺度等价；不能直接换 Adam 后仍把除以 `gamma*E_loc` 的量解释成平均梯度。新更新协议与旧服务器步单独记录，相关理论条件需在实现前核对，不自动宣称原界覆盖新优化器。

### 4.3 预算与训练曲线

- 以 **累计样本处理数／合法交付训练样本数** 定义 effective passes，同时记客户端调用数、本地 optimizer steps、服务器 updates、通信次数和 wall-clock。重复使用小窗口样本不能冒充更多独立数据。
- 离线训练允许缓存并重放训练期已交付样本，按时间顺序重放训练窗口；验证／测试不加入重放。模型版本、方差和 debt 状态的继承规则固定，gate 的校准数据按唯一 unit ID 计数，不能把重放副本计成额外独立校准样本。
- 本地每调用初始预算为 1 个本地 epoch、最多 5 个 minibatch；所有臂相同。低样本窗口记录实际 batch size 与处理样本数。
- 候选模型运行到 100 effective passes，在 `{1,3,10,30,100}` 保存 checkpoint；后半程采用预定的学习率衰减，不能把只衰减后的平坦曲线视为充分训练证明。
- 开发集允许一次扩展到 200 passes。过拟合、发散与尚在学习分别报告；最佳 checkpoint 只由验证集确定。
- 充分训练判据：100→200 的最佳验证 RMSE 改善不足 0.5%，且验证选出的 checkpoint 已超过最强适用简单基线；否则预算仍未充分，停止聚合确认并报告预算不足。0.5%是预算诊断容忍度，不是方法收益阈值。
- 正式四臂采用共同冻结的最大预算；各臂同时输出预算节点和验证选出的 checkpoint。只要某臂开发曲线仍在明显下降，就不能用其它臂先收敛作为结束理由。
- 正式确认中主条件所有四臂延续至 `2B`，在 `B` 与 `2B` 分别报告收益，不在较短预算挑最大方法差。一次训练的 checkpoint 可复用，计算预算仍须计入延续成本。

训练曲线必须同时含训练损失、未加权／部署加权验证 RMSE、最强简单基线水平线、真实样本处理量和更新范数。测试结果在配置冻结后一次性评估，不用于选择 optimizer、epoch 或约束。

### 4.4 学习门槛

先要求 Central-delivered 和均匀聚合骨干均在验证集超过最强适用基线。集中式通过而均匀联邦未通过，说明仍有联邦优化／通信预算问题，不能直接进入 RAVEN 机制对比。正式测试门槛未通过的数据集照常报告，不再换骨干或种子补救。

## 5. 有实际自由度的定义：P2

沿用当前可行域：

`C_r={alpha>=0, sum(alpha)=1, alpha_k<=cbar_r, sum(alpha_k^2)<=1/Ebar_r}`，

其中 `Ebar_r=min(E_min,K_r)`、`cbar_r=min(1,max(alpha_max,1/K_r))`。

均匀权重 `u=1/K_r` 始终可行；当 `Ebar_r=K_r` 或 `cbar_r=1/K_r` 时，可行域退化为 `{u}`。`K_r>3` 只排除原 ESS 约束造成的这种退化，并不证明任务方向可调整。

每个窗口至少记录四层诊断：

1. **几何自由度**：`K_r`、`Ebar_r/K_r`、`K_r*cbar_r`；ESS 给出的位移上界 `sqrt(1/Ebar_r-1/K_r)`。该上界不是实际可达到的半径，cap 可能进一步收紧。
2. **组组成自由度**：对每组求 `min/max_{alpha∈C_r}(M_r*alpha)_g`，记组范围 `W_g` 和 `rank(M_r*(I-11^T/K_r))`。只有权重能移动、组组成全相同时，不能归因于组匹配。
3. **实际权重变化**：`||alpha-u||_1`、`||alpha-beta||_2`、ESS、最大权重、活跃约束、纯投影修复比例及距离。
4. **更新变化**：相同 prestate 下，记录 `||sum(alpha*d)-sum(u*d)||_2`、相对更新差和 cosine。权重不同但客户端更新相同，也不会改善预测。

预定的高自由度机制主条件：NSW-Traffic、`K=8`、`Ebar=0.5K`、`cbar=2/K`，且组成中心化矩阵的rank至少为1、至少两个目标质量非零组具有 `W_g>=0.01`。0.01是设计筛选阈值，使用标签不可见的组成和约束信息，必须在测试前冻结；同时报告满足率、可调整组的部署质量和完全不可达质量，不能把它当作真实数据已具备的属性。时间分组下一个窗口未覆盖所有UTC块可能是正常结构，不能要求每窗覆盖整个时间部署目标；但列组成完全相同的窗口不适合作为组匹配主机制证据。

若该条件供给不足，标记不可执行。不能复制同一客户端凑 K，也不能根据预测效果放宽窗口筛选。几何诊断不要求参考 `beta` 必然被投影改变；若 `beta` 已可行，P=B 是应报告的机制结果。

## 6. 四臂定义与机制归因：P3

四臂使用统一骨干、同样的本地校正损失、同一纠正算法／截断常数、目标、trace、初始化和训练预算。这里的 U 是“校正本地训练下的均匀服务器权重”，不冒称原始 FedAvg。

| Arm | 服务器权重定义 | 回答的问题 | 实现状态 |
| --- | --- | --- | --- |
| U | `alpha=u=1/K` | 统一训练下的权重对照 | 新显式配置 |
| B | `alpha=beta_hat` | 服务器校正参考是否有用 | 参考权重计算已有；须匹配论文 gate 与本地训练 |
| P | `argmin_{alpha∈C} 0.5*||alpha-beta_hat||_2^2` | 仅 cap/ESS 可行投影改变什么 | 新纯投影配置；不能替换成 inst_cal |
| R | 论文完整 RAVEN-MCS 的 P2、debt、variance、staleness 与 aggregate-coverage gate | 完整目标额外带来什么 | 基础组件已有；新训练协议完整集成待核对 |

R 的 P2 保留当前完整形式：

`-Q^T M alpha + (lambda_g/2)||M alpha-mu||² + (lambda_beta/2)||alpha-beta||² + (lambda_v/2)sum(v_k alpha_k²) + lambda_s*tau^T alpha`。

P 将 debt、group、variance、staleness 项全关掉，只保留参考距离与共同可行域。B 允许违反 cap/ESS，报告违反率与稳定性；一旦额外裁剪，它就不是直接参考聚合。

主要差分以相对 RMSE 改善定义，分母明确为各自对照：U→B 检验服务器质量校正；B→P 检验纯可行约束；P→R 检验组匹配、debt、variance、staleness 的合计作用；U→R 检验完整收益。不要把 P 的收益称为组覆盖匹配收益。

### 6.1 两种互补证据

**共同状态的单步诊断**：从冻结的 U 训练轨迹选取预算 `{10,30,B}` 的 checkpoint；对相同 prestate、客户端更新、beta、M 和 gate 分别计算四种权重及更新，只用训练／验证数据。此处才可以逐窗口纯粹归因权重规则。debt 使用共享 prestate 的历史值；这是诊断，不等价于 R 的完整训练历史。

**独立端到端重训**：四臂从同一初始化分别训练，使用公共事件随机数与调度，但模型、debt、variance、校准状态沿各自历史演化。不能在端到端实验中强行复用 U 的客户端更新。

本地校正算法相同，不代表训练分叉后的 gate、beta 和更新数值始终相同。若 gate 依赖模型预测／残差，单步诊断固定共同 prestate；正式 R 保持自己的论文 gate。端到端差分解释为聚合规则及其反馈的总效应，不能宣称全过程只改变一个静态权重向量。

旧 `raven`、`inst_cal`、`twostage_hajek` 不凭名字复用；执行前输出四臂的 policy/config 对照。R 必须完整，包括 gate 的 calibration、bootstrap／覆盖规则和 Design-on/off；缺失时只能标记未集成，不能以 always-on 版本代替。

### 6.2 其余目标项的归因

若 P→R 出现分离，再进行预注册的 matched 消融：R−group、R−debt、R−variance/staleness。保留剩余系数、gate、loss、约束和预算；三个组合检验作为独立的次要检验族。若要单独声称 variance 或 staleness 的贡献，须把最后一个消融拆开。

## 7. 客户端数、约束强度和自然参与

### 7.1 自然参与主实验

三个数据集保留原参与调度，不改变测试部署目标，约束固定为原配置 `E_min=3, alpha_max=0.5`，四臂全部端到端重训。这一轨道用于判断充分训练能否解决原自然参与场景的问题；可调整约束的效果由受控轨道检验。按训练窗口 `K∈{1–3,4–7,8–15,>=16}` 报告窗口数量、target coverage、几何／组成自由度、ESS、权重和更新差。

**训练窗口的 K 不是终局测试查询的属性。** 最终模型用过很多不同 K 的训练窗口，不能直接按其训练 K 给每个测试误差分组，并把它称为某个 K 的因果效果。自然参与的窗口表用于解释训练过程；预测误差对 K 的归因由下述受控端到端实验提供。在线轨道只有在定义了每轮对应的后续查询时，才可以报告按训练时 K 分层的逐轮误差，并明确反馈与时间相关性。

### 7.2 受控机制实验

NSW-Traffic 是预定主机制块；使用真实不同客户端和合法观测池构造预注册调度，公共随机数对四臂一致。提高机会／交付率所得场景明确标为半合成高参与条件，不能冒称原始自然 trace。

- 客户端数：`K={4,8,16}`。
- ESS 强度：`Ebar/K={0.25,0.5,0.8}`。
- cap 固定 `cbar=min(1,2/K)`，形成 9 个训练条件，独立改变 K 和 ESS 强度。
- 主条件固定 `K=8, Ebar/K=0.5, cbar=2/K`；不能看测试后换成更有利条件。
- cap 敏感性：主 K／ESS 条件上额外用 `cbar={1.5/K,4/K}`。因此 cap 与 ESS 不混在同一条“强度”轴上。
- 退化对照：相同窗口置 `Ebar=K`，单步确认 U=P=R 的服务器权重；B 不受该约束，无需与其相等。无需额外完整训练来重复证明这一解析事实。

K 较大时样本通常也更多。受控实验每轮固定总训练记录数及总本地样本处理预算，由 P0 的合法供给决定并在测试前冻结；记录每客户端记录数，不能以重复客户端或隐藏标签补足。另报告自然工作量条件作为系统性能结果。供给不足的格明确缺失及原因，不改为伪造客户端。

K 改变时总客户端层面的归一化影响必须核对；batch／loss 规则和服务器尺度一致。对较紧的 ESS，验证求解器约束残差，不把 fallback 权重当作目标函数已成功求解。

## 8. 度量、统计和停止规则

### 8.1 主次指标

主指标为原始部署目标下 `RMSE_mu=sqrt(sum_g mu_g*MSE_g)`；不能用组 RMSE 的线性平均替代。次指标：物理单位 MAE、WorstGroupRMSE、训练可见度分层误差、Delta_group、Delta_c-s、ESS、更新差、运行时间和通信量。WorstGroupRMSE 的组集合固定，不随权重或支持情况删组。

对未覆盖组同时报告部署目标质量与回退预测误差。仅覆盖组评分另列诊断，不能替代全部部署目标分母。

### 8.2 种子与配对

新建独立命名空间：调参种子 `41001–41003`；开发／方差 pilot `41101–41105`；正式种子 `42001–42020`。每个 seed 内，四臂共享初始化、事件调度、观测噪声、历史遮蔽与 batch 随机数；每个随机源单独记录，避免 method-dependent RNG 消耗改变 trace。

主条件20种子，所有种子保留。敏感性条件5种子，标为探索性区间，不能冒充同等功效的确认。若任一主条件数值失败，按预定规则重跑相同种子并保留失败记录；失败无法恢复时报告未完成配对，不删除坏种子形成优势。

### 8.3 推断与功效

- 每个 seed 先计算完整目标 RMSE，再算配对相对改善 `D_s=(RMSE_control-RMSE_treatment)/RMSE_control`；seed 是条件于固定数据划分的主要独立单位，窗口不能当独立样本。
- 主条件确认族为 U→B、B→P、P→R、U→R 的4个对比；三个自然数据集的 U→R 构成另一个预注册确认族。各族采用配对检验并 Holm 校正，报告原始 p、校正 p、配对均值和95%区间。
- 普通逐对95%区间用于估计，不等价于族错误率控制。若用区间作确认决策，4对比族采用98.75%、3数据集族采用98.333%区间的 Bonferroni 同时覆盖，或预注册 seed-level max-T 同时区间；不可事后挑更显著规则。
- 采用 seed 配对 bootstrap 10,000次，固定分析 RNG `20261011`；探索性报告窗口相关性时采用时间块，不将同种子的多个窗口当作多个独立种子。
- pilot 必须重新训练本协议的骨干和四臂，在验证集估计配对标准差；不使用旧检查点重计分的标准差推断新训练功效。按确认族的检验水平估算 n=20 对2个百分点相对收益的功效／MDE。
- 若 n=20 无法分辨2%收益，本轮标记功效不足并停止正式确认；不追逐0.5%阈值或事后加种子。保留 pilot 和预算建议，后续研究决策单独提出。
- 不要求观察均值“大于自己的事后 MDE”才算显著。MDE用于设计；实际结论以配对推断和预注册实际意义阈值决定。

固定划分下的种子区间只刻画训练／参与随机性，不证明跨地点或季节总体泛化。三个数据集的完整报告提供首批外部范围证据。

### 8.4 超参数公平性

骨干、optimizer、服务器尺度先以 U／集中参照的验证曲线冻结，四臂不按测试分别调优。完整 R 初始系数沿当前配置 `lambda_g=lambda_beta=1, lambda_v=lambda_s=0.1`，但必须核对与新服务器尺度有关的可行性要求。若需要调 R，预注册至多6个科学相关配置，只用验证集，额外预算单列；不同时搜索约束强度、部署目标和测试子集。纯投影 P 没有新增预测调参自由度。

## 10. 顺序、预算与执行边界

1. **P0：元数据／信息条件与供给审计**，不训练。产出任务定义、合法历史覆盖、目标／评分版本、K供给和约束几何。
2. **P1：骨干训练**。每数据集6个集中配置×3开发种子=18；6个本地学习率／服务器尺度配置×3开发种子=18，合计36，三块108条训练轨迹。第二骨干仅在验证不过关时执行同等候选预算，至多另108条。每条含预算节点，100→200延续另计计算量。
3. **P2：几何与共同prestate诊断**，不新训模型；明确主条件是否可执行。
4. **P3开发：主机制条件4臂×5 pilot种子=20条**，只用验证结果冻结配置及功效。
5. **P3确认：自然参与3块×4臂×20种子=240条**；Central-delivered参照3块×20种子=60条。
6. **P3机制：Traffic主条件4×20=80条；其它8个K/ESS格4×5×8=160条，合计240条**。
7. **P4：cap敏感性2格×4臂×5=40条**；三个目标项消融×5=15条，在P→R分离后执行，作为探索性归因。

第一骨干、全部P0–P3及cap敏感性的设计上限为 **708条训练轨迹**（108+20+240+60+240+40）；加目标项消融为723。这个数是分阶段方案的组合计数，不是已批准启动的任务，也不是GPU小时估计。首次pilot记录每轨迹wall-clock、样本量和通信量，再按B/2B、重放次数和候选成本折算实际资源；阶段未通过即停止后续队列。

分配计算紧张时的最小确认包：P1的108条、pilot的20条、Traffic主条件80条、三个自然块240条和Central-delivered的60条，共508条；其余K/ESS与cap格安排为次阶段200条。P2对全部约束网格先做不新增训练的诊断。508条包可以检验主条件和自然参与效果；不同K的终局预测结论须等后续敏感性完成，不能用单步诊断补齐。

最先要完成的是P0与P1，不是一口气启动708条。预算敏感性依靠训练延续checkpoint复用，但其额外计算不能隐藏在“运行条数不增加”中。按验证门槛停止的任务要保留停止原因，不能只保留最终成功块。
