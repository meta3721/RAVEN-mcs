## 原实现异常

`FAILURE_TRACE.txt` 与 `P1_FREEZE.json` 的 `failure` 记录同一次守卫越线：清理前 ESS 残差 `1.4537101800105034e-08`，单纯形 `6.196496649124583e-10`，负值 0，cap 0，冻结上限 `1e-08`。调用栈在锚轨迹的 `runner._process_window`，不是六个已完成决策窗口的评分行。轨迹没有保存精确窗口号，只能落在 36–65。它解释实验为何中断。六个已完成决策窗口的 CSV 状态仍是 `OK`；不能据此说这六窗不合格，也不能说完整 P2 方法整体失效。

## 证据边界

六窗机制观察是探索性的，不是九窗结果，也不是论文主实验收益。

CSV 能核对的是一步风险列：P 与 TwoStage 的 `R_after` 和四组 MSE 相同。`structure_mismatch` 字符串在窗口 1、2、33、34 并不相同，例如窗口 1 的 P 是 `0.36302331346351346`，TwoStage 是 `0.36302331346351335`。窗口 0 和 35 的该字段相同。

向量是否逐位相同，本次没有重新解包 `.npz`。`P1_REPORT.md` 写过六窗局部更新最大差为 0、alpha 最大差约为 `1e-17`。`WINDOW_MECHANISM.json` 记录重叠客户端的局部权重 L1 为 0，同时 P 对 U、F 对 P 的权重 L1 和参数 L2 都不为 0，例如窗口 0 的 `weight_l1.P_U=0.6960322070106655`、`weight_l1.F_P=0.2718392550037395`。这些向量结论沿用原记录，不在本次重新核验。

`FIRST_WINDOW_CHECK.json` 只覆盖窗口 0：公式差 0，重复评分差 0，状态恢复差 0，P 不调用 `solve_p2`，F 调用 P2。`metadata_client_sha_match` 为 false，运行时活动集与冻结元数据摘要不同；这不改变上面的门槛算术。
