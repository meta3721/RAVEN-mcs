# 给执行AI的指令：将论文区间引用展开为逐条引用

请对当前RAVEN-MCS论文执行一次范围明确的引用显示格式修改。实验已暂停，本任务只处理论文排版。

**目标与范围**

所有数字文献引用逐条显示。例如：

`[3]–[7]` 或 `[3–7]` → `[3], [4], [5], [6], [7]`。

每个编号均有独立方括号。不要只改成 `[3,4,5,6,7]`；不要删除区间中间的文献，也不要仅保留两个端点。

同时处理正文、补充材料、附录、表格、图注、脚注中的文献引用。本文献引用要求不适用于公式、图表、页码、年份和数值范围，也不改变参考文献条目里的页码连接号。

不要编辑历史快照、临时构建副本或其他模板目录。若用户另指定了更新的正式稿，先核实入口及其包含关系，在正式稿执行相同任务。

**第一步：记录引用配置与键**

1. 读取入口文件及实际包含的tex文件，检查cite、natbib、biblatex、压缩选项及自定义引用宏。
2. 保存修改前的引用键清单、每次调用的键集合和参考库条目清单，供修改后核对。使用普通小型记录即可，不为此复制整份论文、实验目录或建立新的论文版本。
3. 搜索两类来源：多键cite经宏包自动压缩；源文件手写的方括号区间或 `\cite{a}--\cite{b}` 等显式范围。忽略注释、示例代码、普通数值和参考文献页码范围。

**第二步：优先做最小配置修改**

将两个独立编译入口中的：

```latex
\usepackage{cite}
```

改为：

```latex
\usepackage[nocompress]{cite}
```

保留已有其他必要选项，若已有选项就在同一处加入nocompress；不要重复加载宏包或造成option clash。保留数字排序能力。

当前IEEEtran已经定义 `\citepunct{], [}`，与cite包配合可以生成独立方括号。因此优先只改上述加载选项。不要为了实现逐条显示而把所有多键cite拆成几十条手写编号。

如果项目自身又覆盖了标点，先找到覆盖点，再确保有效设置为：

```latex
\renewcommand{\citepunct}{], [}
```

仅在需要时设置；不要把该设置与额外 `\citeform{[#1]}` 等重复括号方案叠加，造成双层方括号。不要只替换citedash为逗号，这会丢掉区间中间编号。

宏包依据：[CTAN cite包文档](https://mirrors.mit.edu/CTAN/macros/latex/contrib/cite/cite.pdf)，nocompress用于关闭连续编号压缩。

**第三步：处理确实手写的范围**

自动压缩由配置修复。若还存在手写文献范围，则根据最新源码与参考映射恢复区间对应的全部引用键，改为由LaTeX管理的引用。

例如原本实际包含五篇文献时，写成 `\cite{key3,key4,key5,key6,key7}`，由配置输出逐条方括号。例中的key只是说明，不得按例子伪造键或新增文献。

无法确定手写区间对应哪些文献时，给出文件、行号、原文和缺少的信息，不猜测文献身份。不要将静态 `[3]` 作为长期替代，因为编译后编号可能变化。

**第四步：重编译和验收**

1. 使用项目现有构建方式重编译正文与补充材料，完成BibTeX及必要的交叉引用轮次。两入口互有xr引用时，按需要再次编译直至编号稳定。
2. 检查实际新PDF，不使用旧PDF代替验收。先核对输出文件路径和生成时间。
3. 全文搜索 `[数字]–[数字]`、`[数字]-[数字]`、`[数字–数字]`，同时考虑换行、空格、长短横线及减号变体；逐个判定是否文献引用。图表和公式引用不在本任务替换范围。
4. 抽看正文Related Work原来的长引用簇，以及补充材料中实际存在的多键引用：每个文献编号独立加方括号，编号完整，逗号和换行正常。
5. 修改前后引用键及其出现位置应保持等价；参考库不增删。若为手写范围恢复了已有键，单独记录恢复依据。
6. 检查没有新增未定义引用、`[?]`、重复方括号或引用宏错误。若工程保留了超链接，抽查链接仍有效。
7. 记录新PDF页数及是否出现引用簇引起的明显越界。为解决引用簇换行可使用宏包已有断行机制，不通过缩小整篇字号、删文献或改正文内容维持页数。

若本地缺少TeX编译器，先完成可验证的源码修改与引用键核对，明确报告“PDF尚未验收”，并给出Overleaf或现有可用构建入口的复核步骤。不能将未编译状态写成“已全部修复”。
