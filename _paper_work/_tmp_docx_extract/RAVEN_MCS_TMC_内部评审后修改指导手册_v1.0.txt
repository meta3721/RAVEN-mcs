总原则
这不是一次“重新立项”。当前论文的问题定义、R/O/U 信息边界、deployment-target risk、理想顺序重构、P2 可行校准与 claim ceiling 均可保留。本轮只围绕能够真正改变 TMC 审稿结论的漏洞修改：W1/W4 联合修复、真实 mobility 证据、强近邻基线、外部端点、practical estimator 理论与求解审计。
禁止事项
不要为了回应 11 条意见而发明 11 个新机制；不要修改测试集后再调权重；不要把 RMSE/test label 直接写进在线 P2 约束；不要隐藏 U-Air 的负消融结果；不要声称 fully asynchronous、真实系统部署、hidden-confounding robustness 或 universal RMSE superiority，除非新证据真正支持。
1. 修改目标、当前诊断与最终判定标准
1.1 当前稿真正的优点
问题语义已经成熟：明确区分公共 deployment target、arrival/usable-update law、deployment group h(i) 与 opportunity stratum s(i)。
R/O/U 三层选择的 legal-history 信息边界写得清楚，避免 test-label/post-outcome leakage。
理论边界诚实：Proposition 2 只覆盖 ideal/unclipped/正确指定的顺序校正；实际 clipping 不声称 exact unbiasedness。
实验叙事克制：prediction 只声称 competitive / selective gains，不声称 universal superiority；Use/Debt 的弱效应没有被隐藏。
Appendix 已经有 P2 feasibility、Local-Hajek degeneracy、runtime/provenance 等较完整审计。
1.2 当前稿真正可能导致拒稿的四个核心问题
W1：U-Air 上移除 Design 后，Δgroup、RMSE_mu、Tail RMSE 同时显著改善；这与“deployment target 为最高层目标”的叙事形成直接冲突。
W4：实际 propensity 是 estimated + clipped，但论文缺 overlap、calibration、ESS、weight distribution、clipping rate 和 misspecification 证据，导致 W1 无法被科学解释。
W3：没有独立真实移动轨迹/网络更新 replay，TMC 可能认为论文更像 selection-bias methodology，而不是成熟 mobile computing 证据。
W7：Related Work 已引用 participation bias / correlated participation 等近邻，但主实验没有真正加入 target-shift、participation-debiasing、semi-async bias mitigation 的强基线。
只要这四点没有修复，继续增加普通 seed、普通 synthetic scenario、更多 appendix 表格，基本不会改变内部评审给出的 Weak Reject / Reject-and-Resubmit 判断。
1.3 本轮修改的最终通过标准
Design reversal 得到可重复、可解释、可修复的因果诊断；修复后的主方法在 primary deployment endpoint 上不再出现明显方向反转。
实际 propensity 质量被量化，estimated/clipped estimator 的风险与有效范围被报告，而不是只靠理论假设。
至少有一条真实 mobility trace 驱动的 opportunity replay；若 update/network 仍为仿真，必须明确标注 hybrid trace replay。
至少加入 2–3 个真正最近邻强基线，并在 same backbone / same selection trace / same tuning budget 下公平比较。
增加至少一个不直接进入 P2 objective 的外部 deployment endpoint，例如 worst-group prediction error。
Practical estimator 新增一个非平凡误差传播结果：propensity/clipping error -> reconstruction error -> P2 perturbation / deployment mismatch。
主文保持 12–14 页核心叙事；proof、完整统计、solver/provenance 诊断移 supplement。

4. G1：W1 + W4 联合修复 —— 先诊断 Design reversal，再改方法
为什么 W1 与 W4 必须一起做
U-Air 的 w/o-Design 同时改善 Δgroup、RMSE_mu 与 Tail RMSE，很可能不是“Design 理论一定错误”，而是 estimated/clipped Design correction 在有限样本、弱 overlap 或强 clipping 条件下把 corrected reference 拉向了一个不可靠方向。只有先量化 propensity 质量，才能知道应该修 estimator、修 gating，还是修 P2 目标层级。
4.1 第一步：为三层 propensity 建立诊断面板
A. Opportunity/design layer
不要机械套 AUC。opportunity 是 client–stratum/atomic exposure law，优先报告：预测机会质量的 NLL / cross-entropy、预测 mass 与 realized frequency 的 calibration、TV/L1 deviation、support coverage。
报告每个 dataset / stratum 的 pi_hat^opp 分位数：min、p1、p5、p50、p95、max；标记近零 mass。
计算 design ratio zeta 的分位数、最大值、被 a_max 截断的比例，以及截断前后 ESS。
B. Observation layer
对 p_hat^obs 报告 Brier score、calibration curve / ECE、AUC（仅作区分能力，不替代 calibration）。
报告 p_hat^obs 的 min/p1/p5/p50/p95/max、低于 p_min 的比例、对应记录数量。
按 deployment group、opportunity stratum、dataset 分层查看误差，重点检查 U-Air。
C. Usable-update layer
对 q_hat^use 报告 Brier、calibration/ECE、AUC、低 q 事件比例。
按 deadline、staleness bucket、client/window 分层报告；若 Use 当前无效，先确认是不是 q 几乎恒定或 usable censoring 太弱。
报告 d_max 截断比例与 usable correction 对 beta_hat 的实际扰动幅度。

5. G1-B：若诊断确认 practical Design 不可靠，推荐的最小方法修复
重要
下面是“候选修复路径”，只有 G1 诊断支持时才实施。不要为了好看直接把它写进论文。任何新公式都必须重新做 III–VI 理论审计。
5.1 首选：Reliability-aware Design gating / shrinkage
核心思想：当某个窗口/客户端的 opportunity correction 可靠时使用 Design；当 overlap 太差、ESS 太低或 clipping 太强时，将 Design correction 向 no-Design 收缩，而不是盲目使用高方差 inverse ratio。
candidate:  zeta_tilde = 1 + g_{k,r} ( zeta_hat - 1 ),     0 <= g_{k,r} <= 1
g_{k,r} 只能使用 train/online legal pre-outcome diagnostics，例如 ESS ratio、overlap、clip rate、propensity uncertainty。
g=1 对应原 full Design；g=0 对应 no-Design；中间值是 shrinkage。
threshold/gating 参数必须用 training/validation 预先确定，不允许用 test endpoint 调。
至少比较：Full、No-Design、Oracle-Design、Gated-Design 四条线。
5.2 备选：给 deployment-group alignment 更高层级
如果 oracle propensity 下仍出现 Design 反转，但通过提高 lambda_g 可以稳定消除，则说明需要把“deployment group target 优先于 client–stratum fidelity”的层级写清楚。
可以考虑一个只使用公开 target 与当前 feasible support 的 structural no-harm 约束，例如将当前 candidate alpha 的 group mismatch 限制在预声明 safe reference 的容许范围内。
禁止写法
不要把当前 test RMSE 或 test label 直接作为 P2 在线硬约束。RMSE non-inferiority 应当是离线评估标准；在线约束只能依赖公开 target、当前 M_r、合法 pre-outcome 状态与预声明 reference。
6. G2：W2 + W7 —— 加“外部端点”与真正强基线
6.1 外部端点：优先做 worst-group prediction
当前最稳定优势来自 P2 直接优化的结构指标，审稿人会质疑 objective compliance。最有性价比的外部端点是 group-wise prediction error，它不直接出现在 P2 objective 中，但与 deployment target 的业务含义直接相关。
RMSE_g = sqrt( sum_{i:h(i)=g} w_i (Yhat_i - Y_i)^2 / sum_{i:h(i)=g} w_i )
WorstGroupRMSE = max_g RMSE_g
报告四个 deployment groups 的 RMSE_g、worst-group RMSE、group error dispersion。
如果已有 per-record prediction，可以先离线重算，不必重新训练；若没有完整 prediction 则按 frozen seeds 重新导出。
主文只保留 worst-group + overall RMSE_mu；完整 group-wise 表放 supplement。
正式 no-harm/non-inferiority margin 必须在 test 前固定，并给出 paired CI；不要仅用“不显著”当作 non-inferiority。

7. G3：W3 —— 增加真实移动轨迹 / 网络 replay，强化 TMC 属性
内部评审最明确的 venue-fit 批评是：现有 sensing values 是真实的，但 R/O/U 选择过程主要由 protocol 构造。TMC 需要看到 mobility/intermittent connectivity 不只是装饰变量。
7.1 最低可接受方案：真实移动 opportunity replay
使用真实轨迹生成 R：client 在某个 window 内是否覆盖 spatial unit / sensing region，直接由轨迹决定。
将 mobility-derived R 与当前 target field / completion task 对接时，必须清楚说明这是 trace replay，不得写成原数据集本身含移动客户端。
报告轨迹覆盖率、client active fraction、opportunity-stratum visitation distribution、inter-arrival gap、temporal burstiness。
至少比较 Balanced / protocol-generated opportunity 与 real-trace opportunity 下 RQ1/RQ2 的方向是否一致。
7.2 如果已有 T-Drive reviewer-reserve，优先启用
优先把真实轨迹用于验证 opportunity layer，而不是为了凑数据集做一个与主线无关的预测任务。T-Drive 若只提供轨迹，不提供 sensing outcome/network delivery，就只能声称 real-mobility opportunity replay。

8. G4：W5 + W4 —— 新增一个真正有价值的 practical-estimator 理论结果
不要再加一个普通 convexity lemma。最有价值的是把当前 ideal Proposition 2 与实际 estimated/clipped implementation 接起来。
8.1 推荐的新理论链
propensity estimation / clipping error -> normalized reconstruction error -> P2 solution perturbation -> deployment composition error
8.2 建议的假设结构
在目标支持上存在正的 lower bounds：pi_opp >= pi_min、p_obs >= p_min_true、q_use >= q_min_true。
estimated propensity 满足 uniform 或 high-probability error bounds：|pi_hat-pi| <= eps_pi、|p_hat-p| <= eps_p、|q_hat-q| <= eps_q。
显式定义 clipping bias term，而不是把 clipping 当成 0。
Hájek denominator 有正的有效样本下界或高概率下界。
P2 feasible set、M_r 与其他状态固定时，利用已证明的 beta -> alpha non-expansive property。
8.3 目标定理应达到的形式
|| beta_hat - beta_star || <= C1(eps_pi + eps_p + eps_q + eps_clip + eps_sample)
|| alpha_hat - alpha_star || <= || beta_hat - beta_star ||
|| M_r(alpha_hat - alpha_star) || <= ||M_r|| · || beta_hat - beta_star ||
其中常数 C1 必须由 positivity margin、denominator lower bound、weight cap 等明确给出。若只能得到高概率界，也可以；不要写无法证明的“unbiased practical estimator”。
8.4 新理论与实验必须一一对应
理论中的 eps_pi/eps_p/eps_q 对应 G1 的 propensity diagnostics。
eps_clip 对应 clipping rate / threshold sensitivity。
denominator/ESS 条件对应 ESS plots。
P2 perturbation 对应 gated-vs-ungated / oracle-vs-estimated 结果。
这一条理论如果做成，将显著缓解“标准 IPW + convex calibration 拼装”的 novelty 质疑。
9. G5：W9 + W10 —— 统计意义与 P2 数值求解审计
9.1 P2 warning audit
对 warning windows 保存 solver status、primal residual、dual/KKT residual、objective value；如果当前旧日志没有，则在复跑窗口中新增保存。
选一个第二凸优化求解器对 warning windows 交叉验证；至少比较 objective、alpha、M alpha、final metric 的差异。
报告“是否影响主结论”，而不只报告 feasibility residual。
如果第二 solver 与当前结果几乎一致，可将 778 warnings 从风险转为 implementation tolerance 证据；否则必须修 solver 配置并重跑相关 formal runs。
9.2 practical significance
Debt 的 0.002%–0.014% 即便 p<0.05，也必须写成 quantitatively small。
为主要 endpoint 报 paired effect size + 95% CI。
预先定义 minimum practically important difference；如没有外部依据，不要事后凭结果挑阈值。
20 seeds 主要代表 algorithmic randomness，不能替代独立城市/时间段/真实轨迹重复；正文中要明确这一点。

14. 最容易犯的错误：逐条禁止
1. 看到 W1 后直接删 Design。错误：先做 oracle/estimated/overlap 诊断；如果理论 Design 在可靠 propensity 下有效，应该修 practical estimator，而不是删主线。
2. 用 test RMSE 选 lambda 或 gating threshold。错误：所有选择必须 train/validation 或预先规则确定。
3. 把 RMSE no-harm 写进在线 P2 并用当前标签计算。错误：这破坏 legal pre-outcome boundary。在线只能约束公开 target / structural quantities。
4. 为了证明 Use 有用，人工把 usable censoring 调得极端。错误：只有真实 replay 或明确预注册的 stress test 才有价值；不能为组件“造收益”。
5. 把 T-Drive 写成 full real R/O/U system。错误：如果只有 mobility 是真实的，只能称 real-mobility opportunity replay。
6. 加入很多普通 baseline 但没有最近邻。错误：宁可做 2–3 个强 baseline，也不要再加十个弱方法。
7. 只报告 p-value。错误：必须 paired effect、CI、practical threshold；Debt 的 tiny effect 要明确 tiny。
8. 把新的 appendix lemma 当第四个贡献。错误：贡献仍为 risk semantics / reconstruction / calibration 三条。
9. 为了理论深度随意加 convergence theorem。错误：优先补 practical estimator error propagation，这是直接回应 W4/W5 的结果。
10. 改完实验马上改全文。错误：先达到 Gate A–D，再统一写作，避免论文反复漂移。

16. 最终 Go / No-Go 判定
可以重新投 TMC 的情形
W1 不再是未解释的目标反转；最好通过 reliability-aware Design 或目标层级修复稳定解决。
propensity diagnostics + robustness 能说明 practical estimator 在正常 overlap 下可靠，并清楚标出 failure region。
至少一个真实 mobility replay 支持 RQ1/RQ2 的方向。
最邻近强基线加入后，RAVEN 仍能在 deployment alignment + external endpoint 上形成明确价值。
new theory 把 ideal estimator 与 estimated/clipped practice 的 gap 明显缩小。
主文精简、supplement 完整、solver warning 不影响主结论。
暂时不建议投 TMC 的情形
Oracle Design 仍在 U-Air 伤害 primary deployment endpoints，且无法通过合理目标层级解释。
真实 mobility replay 下 RQ1/RQ2 方向消失。
强 baseline 在相同 protocol 下全面达到或超过 RAVEN，而 RAVEN 只剩 Δc-s 小优势。
propensity misspecification / clipping 稍有变化就导致方法不稳定，且无法用 gating 修复。
solver cross-check 表明 warning windows 对结论有实质影响。
给学生的最后一句话
本轮目标不是“把所有审稿意见都写一段回应”，而是让最关键的审稿人质疑失去证据基础。先把 W1/W4 做透，再用真实 mobility、强 baseline 和外部 endpoint 建立 TMC 级证据；其余问题都应服务于这条主线。
