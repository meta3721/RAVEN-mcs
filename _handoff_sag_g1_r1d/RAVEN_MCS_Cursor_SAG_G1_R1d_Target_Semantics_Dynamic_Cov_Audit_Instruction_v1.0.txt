五、R1d-B：定义 current-window opportunity target
=====================================================================

理论对象是：

  P_r^{opp}

它可以随 r 变化。

因此当前 Gate 需要预测的是：

  pi_{k,s,r}^{opp}

不是一个全局静态：

  pi_{k,s}^{opp}。

必须显式区分：

  pooled historical opportunity law
  current-window opportunity law
  lagged predictive opportunity law

------------------------------------------------------------
R1d-B.1 current-window realized reference
------------------------------------------------------------

仅用于 post-window audit，
对每个 completed window r：

  pi_opp_realized(k,s,r)
  =
  N_opp(k,s,r)
  /
  total_N_opp(r)

这是 current-window realized event-mark mass。

它绝对不能进入同窗口 Gate。

输出：

  CURRENT_WINDOW_OPP_REALIZED.csv

------------------------------------------------------------
R1d-B.2 pre-window features
------------------------------------------------------------

只能从 F_{r-} 构造。

允许优先使用已有：

  recent completed pi_opp
  lagged counts
  time block
  public mobility/context
  previous-window opportunity mass
  rolling mean
  rolling trend
  seasonal/time-of-day indicator

禁止：

  current R
  current opportunity counts
  current O/U
  current loss
  current outcome

输出：

  DYNAMIC_COV_FEATURE_AUDIT.md

列出所有 feature，
标记：
  pre-window legal?
  source?
  update stage?

六、R1d-C：构造动态 current-window C_cov certificate
=====================================================================

本轮优先使用“简单、低维、可解释”的动态方法。
不要上神经网络。

推荐主路线：

  predictor for pi_opp(k,s,r)
    +
  one-sided calibrated residual bound

------------------------------------------------------------
R1d-C.1 预测器
------------------------------------------------------------

优先从简单方案开始：

Option 1:
  recent-window rolling predictor

  pi_hat_opp(k,s,r)
  =
  weighted mean of last L completed windows

Option 2:
  time-block-conditioned rolling predictor

Option 3:
  low-dimensional ridge / logistic / multinomial predictor
  using only legal pre-window context

优先使用最简单能工作的方案。

不要同时扫很多模型。

------------------------------------------------------------
R1d-C.2 one-sided residual calibration
------------------------------------------------------------

对 completed calibration windows t：

  residual_{k,s,t}
  =
  pi_hat_opp(k,s,t)
  -
  pi_opp_realized(k,s,t)

为了 lower bound：

  lower_pi_opp(k,s,r)
  =
  max{
    0,
    pi_hat_opp(k,s,r)
    -
    q_{1-delta_cov}
  }

其中 q 必须从 strictly prior / calibration windows 得到。

允许：

A. split-conformal style one-sided residual quantile

B. rolling calibrated quantile

C. block-conformal / block residual quantile

由于 window 内 events 强相关，
优先以“window/block”为 calibration unit。

不要把同一 window 内大量 events 当成 iid calibration samples。

------------------------------------------------------------
R1d-C.3 calibration split
------------------------------------------------------------

必须明确：

  fit history
  calibration history
  evaluation window

不能 current-window 自校准。

如果 history 太短：
  fail closed。

------------------------------------------------------------
R1d-C.4 simultaneous coverage
------------------------------------------------------------

C_cov 依赖多个 target-positive (k,s)。

本轮不强制证明 exact family-wise 95%，
但必须做 empirical joint-window calibration。

至少报告：

  pairwise coverage
  target-mass-weighted coverage
  window-joint coverage
  certified target mass

若 window-joint 远低于 95%，
不得称为 95% simultaneous certificate。

可以采用：
  conservative quantile inflation
  Bonferroni over target-positive pairs
  conformal max-residual calibration

优先推荐：

  max-residual per window：

    R_t
    =
    max_{(k,s): pi_tar>0}
      [
        pi_hat_opp(k,s,t)
        -
        pi_opp_realized(k,s,t)
      ]

然后用 R_t 的 one-sided calibrated quantile：

  q_r

得到：

  lower_pi_opp
  =
  max(0, pi_hat_opp - q_r)

这样直接以 window 为 unit，
更接近 joint support certificate。

------------------------------------------------------------
R1d-C.5 C_cov 公式保持不变
------------------------------------------------------------

继续：

  C_cov_LCB(r)
  =
  sum_{k,s}
    pi_tar(k,s)
    1{
      lower_pi_opp(k,s,r)
      >=
      pi_safe
    }

不得改定义。

=====================================================================
七、R1d-D：动态 C_cov 校准审计
=====================================================================

每个 window post-hoc 检查：

  lower_pi_opp(k,s,r)
  <=
  pi_opp_realized(k,s,r)

注意：
  realized current-window empirical mass 本身有 sampling noise，
  所以该检查是 development diagnostic，
  不是理论真值证明。

必须至少报告：

1. pairwise empirical coverage
2. target-mass-weighted coverage
3. window-joint empirical coverage
4. coverage vs time
5. coverage vs history length
6. certified target mass vs realized support mass

输出：

  DYNAMIC_COV_CALIBRATION.csv
  DYNAMIC_COV_COVERAGE_BY_TIME.csv

------------------------------------------------------------
R1d-D.1 anti-conservatism stop rule
------------------------------------------------------------

若 warm-up 后：

  window-joint empirical coverage < 0.90

或：

  pairwise coverage 明显随时间持续下滑，

则：
  不允许进入 Gate evaluation。
  verdict：
    DYNAMIC_COV_NOT_CALIBRATED

------------------------------------------------------------
R1d-D.2 over-conservatism stop rule
------------------------------------------------------------

若 coverage 很高但：

  C_cov_LCB == 0

或：

  certified target mass 接近 0

在几乎所有 compatible-looking windows 中，

则：
  verdict：
    DYNAMIC_COV_TOO_CONSERVATIVE

不要调 tau_cov。
